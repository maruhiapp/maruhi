`maruhi run -- <command>` keeps values off the disk, but the program it starts holds them in its environment and can print them. For a coding agent that is the whole problem: an agent that runs your program reads its output, and a single `env` or a crash dump puts the values into its transcript. `maruhi proxy run -- <command>` closes that gap for every value a request carries over HTTPS:

- The program receives a **placeholder** for each brokered variable (`mhp_GITHUB_TOKEN_…`, random per run). It cannot print, log, or send a value it never had.
- Its HTTPS traffic goes through a **proxy on your machine**, started and stopped with the command. For the hosts a rule names, the proxy terminates TLS with a certificate authority created for this run, writes the real value in place of the placeholder, and forwards the request. Every other host is tunnelled untouched, with the program's own end-to-end TLS.
- A placeholder used toward any other host, or in a part of the request the rule does not allow, is **refused** with a message that names the variable and the rule. The request is not sent.
- A value the API echoes back is replaced by the placeholder in the response (body and headers; a compressed response is decompressed first), so it does not reach the program that way either.
- With a **connector**, the value written into the request is not a long-lived key but a token minted on your machine just in time — a GitHub App installation token, valid for an hour, from an App key the program never sees.

The maruhi server is not involved and sees none of it. Under end-to-end encryption your values are decrypted on your machine, and with brokering they stay there: neither the server nor the agent holds the plaintext.

## Set up

1. Add `maruhi.proxy.json` to the repository root. It names variables and hosts, never values, so it is committed like any other config file:

   ```json
   {
     "version": 1,
     "variables": {
       "GITHUB_TOKEN": ["api.github.com", "github.com", "*.githubusercontent.com"],
       "OPENAI_API_KEY": { "mode": "broker", "hosts": ["api.openai.com"] },
       "DATABASE_URL": "passthrough",
       "LOG_LEVEL": "passthrough"
     }
   }
   ```

2. Start the agent (or any program) under it:

   ```sh
   maruhi proxy run --env dev -- claude
   ```

   Before the command starts, `proxy run` prints what the program will get: which variables are brokered and toward which hosts, which are passed through with their real value, and which are withheld. When the command exits it prints how many requests were brokered, tunnelled, blocked, or failed. Add `--verbose` for one line per request (method, host, path, and the variable names substituted — never a value).

Inside, `curl -H "Authorization: Bearer $GITHUB_TOKEN" https://api.github.com/user` works, `git push` to GitHub over HTTPS works, and `echo $GITHUB_TOKEN` prints `mhp_GITHUB_TOKEN_…`.

## The config file

| Key         | Meaning                                                                                                                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `version`   | Always `1`.                                                                                                                                                                                                  |
| `project`   | Optional. The project ID this config belongs to; `proxy run` uses it instead of `defaultProject`, and refuses a `--project` flag that names a different project.                                             |
| `unmatched` | What happens to hosts no rule names: `"allow"` (default — tunnelled untouched, never inspected) or `"block"` (the connection is refused). `block` turns the proxy into an egress allow-list for the program. |
| `unlisted`  | What happens to variables no rule names: `"withhold"` (default — not injected; the program does not get them) or `"passthrough"` (injected with their real value, as `maruhi run` would).                    |
| `variables` | One rule per environment variable the program sees. The key is the variable name; the value is a rule.                                                                                                       |

Rules:

| Rule                                                                                         | What the program gets                                                                                                                                                                                   |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `["host", …]` or `{ "mode": "broker", "hosts": […], "surfaces"?: […], "placeholder"?: "…" }` | A placeholder. The real value is substituted only toward `hosts`, only on the listed `surfaces`.                                                                                                        |
| `{ "mode": "connector", "connector": "github-app", "inputs": {…}, "hosts": […], … }`         | A placeholder for a token the proxy mints from the variables named in `inputs`. Those variables are consumed by the proxy and never injected. See [Short-lived tokens](#short-lived-tokens-connectors). |
| `"passthrough"`                                                                              | The real value, as under `maruhi run`. For values a proxy cannot substitute: a database URL used over the Postgres protocol, a key the program needs locally, a non-secret setting.                     |
| `"withhold"`                                                                                 | Nothing. The variable is not injected.                                                                                                                                                                  |

A **host** is `host[:port]`, HTTPS unless written `http://host[:port]`. `*.example.com` matches one or more labels under `example.com` (not `example.com` itself). The default ports are 443 and 80. An IPv4 address is accepted; `localhost` too — `"http://localhost:8787"` brokers toward a local development server in plain HTTP, which is the only case where a value travels unencrypted (and only on the loopback).

**Surfaces** are the parts of a request a placeholder is substituted in: `header` (the default and usually all you need — `Authorization`, `X-Api-Key`, and a `Basic` credential, which is decoded, substituted, and re-encoded), `query` (`?key=…`), `path`, and `body`. The default is headers only on purpose: a value substituted into a body that the API stores — an issue comment, a gist, a chat message — would be published by that API. Add `"surfaces": ["header", "body"]` for an API that takes the credential in the body (an OAuth token endpoint, for example), and keep the rule's hosts to that API.

A **placeholder** is random per run (`mhp_<NAME>_<22 random characters>`). Some clients validate a credential's format before sending it; for those, set `"placeholder"` to a fixed string of the right shape. Placeholders must be unique across rules.

## Short-lived tokens (connectors)

A connector turns a long-lived credential into a short-lived one at the moment of use, on your machine. The first connector is `github-app`:

```json
{
  "version": 1,
  "variables": {
    "GITHUB_TOKEN": {
      "mode": "connector",
      "connector": "github-app",
      "inputs": {
        "appId": "GH_APP_ID",
        "privateKey": "GH_APP_PRIVATE_KEY",
        "installationId": "GH_APP_INSTALLATION_ID"
      },
      "hosts": ["api.github.com", "github.com"]
    }
  }
}
```

`GH_APP_ID`, `GH_APP_PRIVATE_KEY` (the PEM file GitHub gives you when you generate a key for the App), and `GH_APP_INSTALLATION_ID` are ordinary maruhi variables. The program sees `GITHUB_TOKEN` as a placeholder and nothing of the three inputs. On the first request toward a listed host, the proxy signs a short JWT with the App key, asks GitHub for an installation access token (valid for one hour), and writes that token into the request. It re-mints five minutes before expiry. If GitHub refuses, the request is answered with `502` and GitHub's message; nothing is sent to the host.

Compared with a personal access token in `GITHUB_TOKEN`: the credential that exists for an hour has exactly the App's permissions on exactly its installation, and the key that could mint more never leaves the proxy's memory. The maruhi server sees neither.

## What the program sees

- Its environment: placeholders for brokered variables, real values for pass-through ones, and the variables that point its HTTP clients at the proxy and make them trust the run's CA — `HTTPS_PROXY` / `HTTP_PROXY` (and lower-case), an empty `NO_PROXY`, `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`, `GIT_SSL_CAINFO`, `AWS_CA_BUNDLE`, `PIP_CERT`, `CARGO_HTTP_CAINFO`, `NIX_SSL_CERT_FILE`, `GRPC_DEFAULT_SSL_ROOTS_FILE_PATH` (the system roots plus the run's CA), `NODE_EXTRA_CA_CERTS` and `DENO_CERT` (the CA), and `NODE_USE_ENV_PROXY=1` (Node 24's fetch honours the proxy variables only when asked). These are written after the variables, so a variable of the same name cannot redirect the traffic.
- The CA certificate (public) in a private temp directory for the command's lifetime. The CA's key exists only in the proxy's memory; the leaf certificates are issued per host and die with the process. Nothing else is written.
- On a refused request, a plain-text answer such as `maruhi proxy: the placeholder for GITHUB_TOKEN is only substituted toward the hosts its rule names (this request is for api.example.com:443); the request was not sent` — so an agent learns why and can tell you.

Clients that honour the proxy and CA variables: curl, git, the GitHub CLI, Python (`requests`, `httpx`, `urllib`), Ruby, Go, Deno, Bun, Node 24 and later with built-in `fetch` (via `NODE_USE_ENV_PROXY`) and Node with `undici`'s or `axios`'s proxy support. Java needs its own `-Dhttps.proxyHost` flags and trust store. A program that ignores these variables simply does not go through the proxy: it sends the placeholder to the host and gets an authentication error, and nothing leaks.

## Limits

- **The variables are advisory.** A program (or an agent) can unset `HTTPS_PROXY` and connect directly — it then sends the placeholder and fails, which is the safe outcome; it still cannot obtain a brokered value. What it can do is run `maruhi run` itself, if it has your session: on your workstation, `proxy run` protects against programs that misbehave, not against a program with your keychain and the will to use it. For a guarantee, run the agent in a sandbox or container without your keychain or `MARUHI_TOKEN`, started from `maruhi proxy run` on the host side (the proxy listens on the host's loopback — give the sandbox access to it, for example with Docker's `--network host`).
- **Not substituted:** a placeholder transformed by the client before sending — base64 outside a `Basic` header, a hash, a signature. Signature schemes that sign with the credential (AWS SigV4) cannot be brokered this way; use the cloud's federation (OIDC → STS) instead, and pass through what remains. A credential whose format the client parses as a JWT is likewise not supported.
- **Only HTTP and HTTPS.** A Postgres connection string or an SSH key is used over its own protocol; declare it `passthrough` and rely on the run-output redaction below.
- **Brokered hosts are intercepted**, so a client that pins its certificate for such a host, or needs mutual TLS to it, fails. Hosts no rule names are not intercepted. WebSocket upgrades toward a brokered host are refused; request bodies over 32 MiB toward a brokered host are refused (send uploads to a host no rule names). HTTP/2 is negotiated down to HTTP/1.1 on brokered hosts.
- **The proxy itself does not use an upstream proxy.** Behind a corporate proxy, the run's proxy reaches the hosts directly.
- **Anyone on the machine can connect to the proxy's port** (it is on the loopback for the command's lifetime). Without a placeholder, nothing is substituted; a placeholder is a capability for that one run and is visible to whatever the program shows it to.

Review changes to `maruhi.proxy.json` the way you review a CI workflow: it decides which host receives which value.

## Output redaction (`maruhi run` and `proxy run`)

Pass-through values still enter the program, and `maruhi run` injects every value. When the output of such a program may land somewhere other than your terminal, maruhi scrubs it: the program's stdout and stderr are relayed through the CLI and every injected value — whole, line by line, and in its JSON-escaped form — is replaced by `[redacted]`, byte for byte, as it streams. It triggers when a known AI agent is detected, or when stdout or stderr is not a terminal (a pipe, a redirect, CI). Running `maruhi run` yourself in a terminal changes nothing: the program keeps the terminal.

It is exact-match, so it catches `maruhi run -- env`, a config dump, a stack trace with the environment in it — and not a value the program transformed (base64, a hash, another encoding). Binary output is not altered. Treat it as a second line of defence; keeping values away from the program is what `proxy run` is for.
