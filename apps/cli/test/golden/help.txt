$ maruhi
DESCRIPTION
  Diskless secrets manager: values are encrypted end-to-end and decrypted only in memory, never written to disk

USAGE
  maruhi <subcommand> [flags]

GLOBAL FLAGS
  --help, -h       Show help information
  --version, -v    Show version information

SUBCOMMANDS
  login       Sign in by approving a request in your browser, and store the token in the OS keychain (or in the current `maruhi agent` session)
  logout      Revoke this machine's token and remove it from the OS keychain (or from the current `maruhi agent` session)
  pull        Verify the project and environment, decrypt the values in memory, and list the variables (names, versions, and sizes; values only with --show)
  run         Decrypt the environment and run a command with the values injected as environment variables (memory only). Write the command after `--`
  push        Encrypt a value read from stdin and push it to the environment (one trailing newline is stripped), then sync the deploy targets whose config asks for it
  agent       Hold the token and master key in memory for the lifetime of a command, for machines without an OS keychain (ssh-agent style; nothing is written to disk). Write the command after `--`; `agent status` shows what the session holds
  ci          Commands for CI jobs (run / sync)
  env         Manage environments (create / rotate / diff)
  server      Manage selective disclosure to the server (grant / revoke)
  invite      Manage invites (create / accept / list / revoke)
  member      Manage members (add / remove / change-role / list)
  approval    Four-eyes proposals (list / show / approve / withdraw)
  key         Manage this device's key and your reserve key (generate / show / publish / recover / recovery / seal / reserve)
  device      Manage your device keys (add / approve / list / revoke)
  token       Manage your API tokens (list / revoke)
  guardian    Manage guardians for reserve-key recovery (add / approve / list / remove / wards)
  project     Manage projects (init / list / verify / anchor / checkpoint / policy)
  rotation    Manage rotation flags (list / dismiss)
  audit       View and verify audit events (list / invites / self / verify / reconcile). Bare `maruhi audit` runs list
  config      Manage non-secret settings (get / set). Secrets are never stored here
  schema      Show the environment's declared variable schema (names, types, required, status, descriptions; no values). Bare `maruhi schema` shows; `schema set` writes
  var         Manage variables (rm). push / pull / run operate on values directly
  sync        Copy variables to deploy targets (init / plan / apply) through the installed vendor CLI or the vendor API. Targets are declared in the sync config committed in the repository

USAGE
  maruhi sync <subcommand> [flags]

GLOBAL FLAGS
  --help, -h       Show help information
  --version, -v    Show version information

SUBCOMMANDS
  init     Print a sync config for one deploy target as JSON to stdout (commit it as maruhi.sync.json). Reads nothing and contacts no server
  plan     Show which variables an apply would write to or delete from a deploy target, by name and version (the values are not decrypted, and nothing is read back from the target)

$ maruhi sync init --help
DESCRIPTION
  Print a sync config for one deploy target as JSON to stdout (commit it as maruhi.sync.json). Reads nothing and contacts no server

USAGE
  maruhi sync init [flags] <target>

ARGUMENTS
  target string    Target name from the sync config (a key under `targets`)

FLAGS
  --preset string        Deploy target kind: vercel, cloudflare-workers, netlify, or github-actions (required)
  --driver string        How to reach the target: exec (the installed vendor CLI; default when the preset has one; the only driver for github-actions) or http (the vendor API with a token stored in maruhi; the only driver for netlify)
  --env string           maruhi environment ID to copy from (required)
  --receipts string      maruhi environment ID that stores the receipts (required; create it with `maruhi env create`)
  --project string       Project ID to pin the config to (optional)
  --variables string     Comma-separated variable names to copy (default: "all")
  --exclude string       Comma-separated names to leave out (only with the default "all")
  --production           Mark the target as production (apply then needs --yes; the default follows the preset)
  --cwd string           exec driver: directory to run the vendor CLI in, relative to the config
  --command string       exec driver: path of the installed vendor CLI (default: on PATH)
  --token-env string     http driver: maruhi environment ID that holds the vendor's token
  --token-name string    http driver: name of the maruhi variable that holds the vendor's token
  --on-push string       Sync after every `maruhi push` to the environment: apply (from this machine) or workflow (trigger the repository's workflow with gh so CI syncs); needs --project
  --workflow string      With --on-push workflow: the workflow file that runs `maruhi ci sync` (for example maruhi-sync.yml)
  --option string        Preset option as key=value (repeatable; for example environment=production, name=my-worker)

GLOBAL FLAGS
  --help, -h       Show help information
  --version, -v    Show version information
