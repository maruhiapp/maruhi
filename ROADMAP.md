The trigger conditions are **not identical** to the value-display gate (agent-gate.ts's `ensureValueDisplayAllowed` = known-agent detection ‖ stdin non-terminal ‖ stdout non-terminal) but the following 2 layers — (1) known-agent detection (the secondary layer. An agent that allocates a PTY has stdout as a terminal, so without this the `run -- printenv` bypass stays open), (2) stdout or stderr is non-terminal (CI, pipes, unknown agents). **stdin being non-terminal alone is not included**: the trigger substitutes the child's stdout / stderr with pipes (non-TTY from the child's view), so it doesn't break the child's TTY even for a human heredoc-ing `run` — as long as the output destination is a terminal, values don't land in a file. If a human pipes `run -- cmd | tee log`, (2) triggers and no value remains in the log, consistent with the diskless invariant (as intended). Residual: an unknown PTY-using agent is caught by neither (1) nor (2) (fail-open) — the root fix is `proxy run`. When triggered, the child's stdout / stderr is received on pipes and the injected plaintexts (and their JSON-escaped forms) are replaced with `[redacted]` longest-fragments-first, then streamed. The mechanism **shares only the fragment-set construction (raw values, line-split forms, JSON-escaped forms, longest-first) from `maruhi sync`'s output redaction (sync-exec.ts's scrubVendorOutput)** — that function assumes a full buffer for one-shot display on failure (`keepTail` / `SHOWN_TAIL_LINES`), so it doesn't fit `run`'s incremental output as-is. **Streaming design points (rulings)**: (a) a value straddling a chunk boundary would pass through (same shape as "cut before masking and the second half of a value crossing the cut won't match" in the same file), so matching happens in the **byte domain**: the fragment set (strings) is UTF-8-encoded into byte strings used as search patterns, and the child's stdout / stderr `Uint8Array` chunks are searched and replaced undecoded — no decode / re-encode in between, **preserving byte transparency of the child's output** (binary output like `run -- pg_dump -Fc > dump` or `tar czf -` isn't corrupted in CI. `TextDecoder`-based matching is not taken because its non-fatal default replaces invalid UTF-8 with U+FFFD). The ProcessRunner side keeps **a boundary buffer carrying (the longest encoded fragment's byte length − 1) into the next chunk** (the unit is bytes, same as matching) and only masks and streams the confirmed prefix (the carry-over is flushed last when the child exits). The carry-over may be truncated at a newline (0x0A) boundary (line-split fragments cover each line, so values of multi-line form are caught per line; the JSON-escaped form contains no raw newline so it can't be cut at one) — shrinking the delay bound to "the bytes of the longest single-line fragment" (live logs stream line-by-line even for multi-line values like PEM keys). Residual: a value appearing in a non-UTF-8 encoding (a Windows tool writing UTF-16, etc.) isn't caught — same classification as transforms like base64. (b) "buffer everything and mask at once" loses incremental output and is incompatible with `ci run`'s live logs (debugging in CI), so not taken. (c) Piping brings relaying, exit-waiting, and signal forwarding into ProcessRunner's responsibilities (currently `inherit` — live.ts's makeBunProcessRunner). The change is confined to the CLI (live.ts's ProcessRunner + sharing the fragment construction); crypto / server / spec unchanged. A human TTY is inherited as before. Unlike Unbound-style regexes / entropy detection (guesswork = fail-open), the injecting side knows the values, so it can mask by exact match. **Limitations stated**: transformed output (base64 etc.) isn't caught, so this is a second line of defense — the root is `proxy run`. However, for values a proxy can't substitute (connection strings used over non-HTTP protocols, signing/encryption keys needing local plaintext, `ci run` logs) the real thing still enters the child even after the proxy lands, so this item survives the proxy — built into the proxy design as "protecting unsubstitutable values". May be bundled with the proxy for timing (no design backtracking)
