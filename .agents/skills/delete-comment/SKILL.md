# Deleting code comments (ADR-0020)

Prose code comments are banned in this repository. Decision records live in
ADRs; narration lives nowhere. This skill is the repeatable process for a full
comment audit and for one-off removals (for example when the comment ratchet
fails on a comment you added). Policy and rationale: `docs/adr/0020-comment-policy.md`.

## The five categories

Classify every comment into exactly one category:

- **Tautology** — repeats what the code already shows (narration, restated
  names, step summaries). Delete.
- **Stale** — references code, sections, or implementation details that no
  longer exist, including commented-out code. Verify the referenced thing is
  really gone (grep) before marking Stale. Delete.
- **Excuse** — presents a hacky implementation as acceptable ("temporary",
  "for now", a workaround with no revisit condition). Delete the comment AND
  file a GitHub issue (`gh issue create`, English) describing the hack and the
  proper fix. A workaround note that documents the external constraint plus a
  revisit or fail-loud condition is not an Excuse — it is a Decision Record.
- **Decision Record** — documents a non-obvious decision: rationale, rejected
  alternatives, invariants, external constraints, security judgments. Move it
  into an ADR (below), then delete the comment.
- **Functional** — machine-read or load-bearing text. NEVER delete, never
  count as prose:
  - import-lint tags (`@public`, `@package`, `@private`, `@access` in JSDoc)
  - suppression directives and their reason comments (`fallow-ignore-next-line
    <rule> -- <reason>`, `oxlint-disable`, `eslint-disable`,
    `shellcheck disable=`, `actionlint ignore=`, `@ts-expect-error` /
    `@ts-ignore` / `@ts-nocheck`, `@vite-ignore`, `/// <reference ... />`)
  - `english-exempt` markers
  - license/copyright headers, codegen banners ("Generated by", "DO NOT EDIT",
    `@generated`)
  - bare pinned-action version tags in workflows (`# v7.0.1`)
  - config-file comments that are the operator documentation of record
    (`.fallowrc.json` suppression reasons, `.importlintrc.jsonc` option
    documentation, `cloudflare.config.ts` explanations) — classify these
    Decision Record or Functional, never Tautology

Tie-breakers (mandatory): prose-vs-Functional doubt → Functional.
Tautology-vs-Decision-Record doubt → Decision Record.

Area rules: `packages/crypto` comments anchoring to CRYPTO_SPEC sections or
test vectors default to Decision Record, never Stale unless the referenced
section demonstrably no longer exists. Dated records (`docs/adr/`,
`docs/notes/`, dated ROADMAP notes) are documents, not code comments — never
rewrite them. `docs/**` prose is out of scope.

## Process

### 1. Census

Extract every comment in scope (`apps/*`, `packages/*`, root configs,
`scripts/`, `actions/`, `packaging/`, `.github/`; not `docs/**`, `node_modules`,
`dist`, `.git`, `.agents/`, `.claude/`, `.deepsec/`). A comment "unit" is one
prose comment: consecutive `//` (or `#`) lines merge into one unit; a
`/* */` / `/** */` block is one unit; HTML comments in `.astro` count.

Extraction pitfalls, all observed in the 2026-11-21 audit:

- A raw token scanner desyncs on template-literal substitutions and silently
  swallows later comments. For TS-family files use a full parse
  (`ts.createSourceFile` + node walk over leading/trailing comment ranges)
  unioned with a state-machine scanner (the parse alone misses JSDoc on
  union-type members). The repo pins TypeScript 7, which has no classic JS
  API; load the classic 5.9.3 copy from the Bun store via `createRequire`.
- In `.astro` files, a literal `<style` or `<script` inside an earlier comment
  creates a phantom element span that shadows real HTML comments. Cross-check
  the census against the ratchet scanner (step 5) and against a naive
  `<!--` sweep per astro file.
- The state-machine scanner desyncs on apostrophes in JSX text
  (`apps/web/src/dashboard/DashboardShell.tsx` is the known case); the parse
  is authoritative there.

Keep a machine-readable inventory: file, start/end line, kind, raw text, and
(after step 2) category, a ≤140-character note, and an ADR theme for Decision
Records.

### 2. Classify

Apply the rubric above to every unit. Decision Records get a one-line
distillation of the decision and a theme (the 2026-11-21 themes:
`testing`, `crypto-protocol`, `cli-behavior`, `server-data-do`, `server-auth`,
`platform-ops`, `api-contracts`, `gate-config`, `web-trust`, `misc`). Excuses
get a note stating the hack and the proper fix. Mark genuinely doubtful items
and have a second reader disposition them.

### 3. Act

- Tautology / Stale: delete.
- Excuse: delete, and file one GitHub issue per excuse (group only when
  several share one fix and one location cluster). Cite file, the comment
  text, and the code context at the base commit — line numbers shift after
  deletions.
- Decision Record: relocate into ADRs under `docs/adr/` (next free numbers),
  grouped coherently by theme — a small number of ADRs, not one per comment.
  House format: `# ADR-NNNN: Title`, Status line, `**Context**`,
  `**Decision**`, `**Rationale**`, `**Consequences**`; register each new ADR
  in `docs/adr/README.md`. Where an existing ADR or spec already records the
  decision, that record satisfies the move — do not duplicate it. In code,
  delete the comment; leave a one-line pointer (`// See ADR-NNNN.`, `#` in
  toml/yaml/shell) ONLY where a reader of that exact spot would otherwise make
  a wrong change (gate and operator configuration). Every pointer counts as a
  remaining comment in the ratchet baseline.
- Functional: leave untouched.

Apply deletions mechanically with per-unit assertions (the segment at the
recorded lines must contain the recorded text) in descending line order per
file, then run the formatter (`bun x vp fmt` on the changed files) to repair
spacing artifacts such as double blank lines.

### 4. Verify the tree

- `bun run importlint` exits 0 (a deleted `@public` tag breaks this).
- Full `bun run check` from the root is green. Note the `doc-paths` test
  (`apps/site/test/unit/doc-paths.test.ts`) resolves file references inside
  comments: deleting a referencing comment is safe, but a pointer left behind
  must not carry a wrong path — pointers are plain `See ADR-NNNN.` for this
  reason.

### 5. Regenerate the ratchet baseline

The ratchet is `packages/core/test/comment-ratchet.test.ts` (part of
`bun run check`). It scans the tree with a state-machine scanner, exempts
Functional comments by the patterns in its `isFunctional`, and compares the
remaining prose comments per file against
`packages/core/test/comment-ratchet-baseline.json`. Any new prose comment, or
any change to a baselined remainder, fails the test.

After any audit or removal that changes the remaining set, regenerate:

```sh
COMMENT_RATCHET_UPDATE=1 bun x vp test run packages/core/test/comment-ratchet.test.ts
```

Then run the test again without the variable and confirm it passes, and prove
the ratchet still bites: add a throwaway prose comment to any scanned file,
confirm the test fails naming the file and the comment, and revert the probe.
Never hand-edit the baseline, and never regenerate it to silence a failure
caused by a comment that should have been deleted or relocated instead.

For a one-off removal (a single comment), steps 1–2 shrink to reading the
comment and classifying it in place; steps 3–5 are unchanged.
