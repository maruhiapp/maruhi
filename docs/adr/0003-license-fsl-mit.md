# ADR-0003: Licenses are FSL-1.1-MIT (server) + MIT (CLI/SDK/crypto)

**Status**: Accepted (final; carried out with owner approval on 2026-08-12)
**Context**: We want to forbid third parties from offering a competing cloud service. AGPL cannot prohibit the offering itself.
**Decision**: Server = FSL-1.1-MIT (prohibits competing use only; auto-converts to MIT after 2 years). CLI / SDK / crypto = MIT.
**Rationale**: The only option that permits self-hosting and personal use while still banning a competing SaaS. The 2-year MIT conversion also tells a trust story: "even if the author disappears, the asset remains".
**Consequences**: Does not call itself OSI "open source" (described as source-available / Fair Source). DCO + the license clause in CONTRIBUTING.md are required at publication. Closed development until then.
**Implementation record**: 2026-08-12, the LICENSE set was introduced on main (root / `apps/server` / `apps/web` = FSL-1.1-MIT full text, `apps/cli` / `packages/{crypto,core,api-schema}` = MIT, CONTRIBUTING.md [DCO 1.1], README license section, and the license field of each package.json). The repository default is FSL-1.1-MIT; MIT overrides it via per-directory LICENSE files.

**Revision 1 (2026-11-28 — owner decision): the DCO sign-off is asked of pull requests from forks, and CI checks it.** CONTRIBUTING.md asked every commit for a `Signed-off-by` trailer, no commit on main carried one, and nothing checked it (AUDIT_REVIEW_2026-09-26 C-1). The DCO is a contributor's statement that they may submit the work under the license of the directory they change; it protects the project when it takes in another person's code. So the rule now names that case: every commit of a pull request from a fork carries a sign-off with its author's email address, and `.github/workflows/dco.yml` fails the pull request otherwise. Maintainers push their own work to branches of this repository and do not sign off. Rejected: asking every commit (the maintainers' own commits, the squash commits on main and the commits an agent writes for a maintainer would each need a trailer that protects nothing), dropping the DCO for the license clause alone, and a CLA (a stronger grant than the project needs, at a cost to each contributor). The line is "from a fork" and not the author's association with the organization: only an account with write access can open a pull request from a branch of this repository, the event states it without an API call, and it does not depend on whether a membership is public.
