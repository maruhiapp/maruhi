# ADR-0013: The web UI library is Astryx (replacing HeroUI v3 / Pro + Tailwind v4)

**Context**: It turned out that HeroUI Pro is under a proprietary license (sharing/publishing/redistributing components and source is prohibited; a license token is required) and cannot be included in the self-hosted web dashboard, which is an OSS distribution. The migration candidates compared were Astryx (Meta, MIT, StyleX-based, released 2026-06, used inside Meta for 8 years across 13,000+ apps) and React Aria Components (Adobe, already a monopackage, with an official agent skill + MCP). Measured, both have equal footprints at 16 packages / ~72MB, but Astryx's prebuilt-CSS approach removes the Tailwind toolchain itself. RAC is superior on robustness (8 years of public compatibility history, codemod culture).
**Decision**: The UI library for apps/web is Astryx. Tailwind v4 is not adopted (oxfmt's Tailwind class sorting is also disabled). Spike A's verification target is changed to "Astryx × FunStack (the `"use client"` boundary with the RSC static shell; serving prebuilt CSS via Workers Static Assets)".
**Rationale**: (1) Dependencies are minimized system-wide (the entire Tailwind layer disappears). (2) Agent-first design — the CLI ships typed JSON, a capability manifest, and `--lang dense`; `init --features agents` generates AGENTS.md / CLAUDE.md; `doctor` becomes a CI gate. (3) Token-level customization (defineTheme) separates behavior/a11y (system side) from appearance (theme side), which suits long-term consistency. (4) The owner judged the new beta (0.x) risk acceptable (2026-08-01).
**Consequences**: 0.x semver carries breaking-change risk. Mitigation: exact pinning + updates as separate PRs using the `astryx upgrade` codemod + `astryx doctor` wired into CI. Stable only, no canary. Fallback path: React Aria Components + Tailwind v4 (retreat to headless and write the style layer ourselves). The HeroUI Pro license is not used in this repository (if used at all, only on a private marketing site). The styling discipline (no className / style, etc.) is defined separately as a convention.
