# ADR-0020: Prose code comments are banned; decision records live in ADRs

Status: 2026-11-21. Accepted on merge of the PR that adds this ADR.

**Context**: On 2026-11-21 the repository ran a full audit of its code comments. The census found 16,904 comments (59,622 comment lines) across 990 files. (The parse-based census missed exactly one comment — an HTML comment in `apps/site/src/pages/index.astro` shadowed by a `<style` mention inside an earlier comment; the ratchet's independent scanner caught it in cross-check, and it is included in these totals.) Every comment was classified:

- **Decision Record** — 10,341 comments (49,964 lines): non-obvious decisions (rationale, rejected alternatives, invariants, external constraints, security judgments) recorded only at the code site.
- **Tautology** — 6,271 comments (9,019 lines): narration that repeats what the code already shows.
- **Stale** — 4 comments (21 lines): references to things that no longer exist, including commented-out code.
- **Excuse** — 0 comments: no comment presented a hacky implementation as acceptable. Workaround-shaped comments all documented the external constraint plus a revisit or fail-loud condition, which makes them Decision Records.
- **Functional** — 288 comments (618 lines): machine-read or load-bearing text (import-lint tags, suppression directives and their reasons, `@ts-expect-error` directives, `english-exempt` markers, license headers, codegen banners, formatter directives). These are not prose and are out of scope for this ADR's ban.

Nine units were initially misclassified as prose and corrected to Functional on coordinator review before the audit closed: seven JSDocs carrying an `@public` import-lint tag (their tags are restored as bare `/** @public */`; the decision content of three of them remains recorded in ADR-0023), one `english-exempt` marker in a test-vector generator (restored verbatim), and the do-not-edit header of the hash-pinned BIP39 word list (restored verbatim; its spec correspondence remains indexed in ADR-0022).

Two conclusions followed. First, the prose bulk was mostly narration and trapped records: the code carried ~59,000 lines of comments, yet the actual decisions had no reviewable home — a comment cannot be proposed, reviewed, or revised as a decision. Second, deleting the narration without a ratchet would only restart the accumulation.

**Decision**:

1. **Prose code comments are removed and banned.** Tautology and Stale comments are deleted. Decision Record comments are deleted from the code after relocation (decision 2). Excuse comments, when one appears, are deleted and filed as a GitHub issue describing the hack and the proper fix; the 2026-11-21 audit found none.
2. **Decision records live in ADRs.** The relocated records are grouped by theme in ADR-0021 (test suites), ADR-0022 (cryptographic protocol), ADR-0023 (CLI behavior), ADR-0024 (server data plane and Durable Objects), ADR-0025 (authentication and authorization), ADR-0026 (platform and operations), ADR-0027 (API contracts), ADR-0028 (quality-gate configuration), ADR-0029 (web trust boundary), and ADR-0030 (miscellaneous). In code, a one-line `See ADR-NNNN.` pointer is left only where a reader of that exact spot would otherwise make a wrong change (gate and operator configuration); every pointer counts as a remaining comment in the ratchet baseline.
3. **Functional comments are exempt by pattern**, as enumerated in the Context. The exemption is a pattern list in the ratchet test, not a judgment call per comment; a comment that matches no Functional pattern is prose.
4. **A ratchet enforces the ban.** `packages/core/test/comment-ratchet.test.ts` scans the tree, exempts Functional comments by pattern, and compares the remaining prose comments against a generated baseline (`packages/core/test/comment-ratchet-baseline.json`) that lists exactly the post-audit remainder: the ADR pointers, plus the Functional comments that match no exemption pattern (suppression reasons in `.fallowrc.json`, option documentation in `.importlintrc.jsonc`, and similar operator annotations). Any new prose comment, or growth in any file, fails `bun run check`. The baseline is regenerated only as part of the `/delete-comment` process, never by hand.
5. **The repeatable process is a repository skill.** `.agents/skills/delete-comment/SKILL.md` documents the census → classify (with the Functional guardrail) → act (delete / issue / ADR) → regenerate-baseline procedure, so a future audit or a single-comment removal follows the same rules.

**Rationale**: (1) Code is the record of what the system does; ADRs are the record of why. Mixing the two made the "why" unreviewable and let narration accumulate until it drowned the records. (2) A ban without a ratchet decays; a ratchet without the Functional exemption would break machine-read comments (import-lint tags, suppression reasons) that the gates themselves depend on. (3) Relocating records instead of summarizing them away preserves all 10,345 decisions verbatim in substance; nothing the comments knew is lost.

**Consequences**: The codebase sheds ~59,000 comment lines; the only prose comments remaining are the seven ADR pointers in gate and operator configuration files. Reviewers who need the reasoning behind a code site consult the theme ADR (line numbers there refer to the audit base commit `0f036bef`) or git history. New decisions are written as ADR entries, not comments — a PR that adds a prose comment fails the gate until the comment is removed or the decision is moved into an ADR and the baseline is regenerated through the `/delete-comment` process. The ratchet baseline is a generated file; it is large only if prose comments return, which is the failure it exists to report.
