# ADR-0014: 製品進化方針 — ゼロ知識チーム秘密基盤を本線とし、エージェント隔離を次の楔にする

Status: 2026-08-07 提案。PR #37 のマージをもって所有者承認(Accepted)とする。**改訂 1**(2026-08-30 H0 — 決定 5 のホステッド順序の差し替え。裁定録は docs/notes/session-47.md、設計は docs/notes/hosted-design.md)は本改訂を含む PR のマージをもって承認。

**Context**: 競合比較の議論(2026-08-07)で位置づけが整理された。dotenvx = 暗号化 `.env`、Varlock = AI-safe 設定レイヤ(schema・リーク検知・credential proxy)、Keyway = サーバー側暗号化 vault(体験は近いが信頼モデルが違う)、Infisical = 本命競合(vault + diskless run + agent proxy)、1Password / Bitwarden = 隣接競合(人間 vault の信頼と導入済み効果)。重要な補正: **ディスクレス注入は Infisical にもあり、単体では差別化にならない**。maruhi の差は「ゼロ知識・選択的開示が既定か」「`.env` 生成を禁止するほどディスクレスを不変条件にしているか」「メンバーシップ・真正性をどこまで暗号で縛るか」にある。

**Decision**:

1. **本体は選択的開示 E2EE のチーム秘密基盤(ADR-0002 の再確認)**。勝ち文句は「絶対最安全」ではなく「信じなくてよい相手の範囲が競合より広い」。ディスクレスは必要条件だが独占ではなく、不変条件(CLAUDE.md 絶対規則)として守り続ける
2. **エージェント隔離を Phase 3 の本線に昇格する**。優先度順: ① 値なしスキーマ(名前・型・説明・必須のみをエージェントへ開示。`maruhi schema` / MCP。`.env.schema` ファイルは正にしない)→ ② credential brokering(`maruhi proxy run`: エージェントにはプレースホルダのみ渡し、通信境界で実値に差し替える。E2EE ストアと組み合わせ「サーバーもエージェントも平文を持たない」まで一貫させる)→ ③ JIT / DO リース → ④ no-reveal 方針化(人間向けの値表示を例外操作に格上げ。エージェント検出時の表示拒否は既定のまま)→ ⑤ リーク検知・ログ redact(付帯機能)
3. **人間エラー対策は「教育」ではなく機構で行う**: no-reveal・broker 経由・短命資格情報・承認付き break-glass(四眼。企業向け後続)・要ローテーション検出(→ 可能な範囲で上流自動ローテ)。「人間は秘密を持てない」を既定にはしない(開発者ツールとして採用されない)
4. **リカバリーは「読めない形で補助する」**: 運営がキットを預かって復元できる形は、選択的開示より悪い信頼集中でありゼロ知識を壊すため禁止。対策は Phase 1 のリカバリーコード UX の丁寧化 → ユーザー所有ストレージへの封印バックアップ(パスフレーズ / パスキーで暗号化)→ パスキー PRF によるキット依存の削減(CRYPTO_SPEC 未決 #2)
5. **導入の重さは切り分けて語る**: クラウド利用時の日常体験(ログイン → 秘密投入 → `maruhi run`)は Keyway 級に軽くできる。ゼロ知識の代償として残る儀式(初回の鍵生成・リカバリーキット保存、招待時の指紋確認、端末移行)は隠さず「初回と招待だけ」と正直に切り分ける。セルフホストは上級者経路、クラウドは「最初の 5 分」として見せる。~~**ホステッドクラウド版は前倒ししない(本 ADR の裁定)**: Phase 1 の完了条件(ドッグフーディング)と Phase 2 の公開が先であり、着工日 = WorkOS 再判断ポイント(ADR-0009)を維持する。「最初の 5 分」は着工時のホステッド版に課す体験要件として本 ADR が引き継ぎ、それまでの導入経路はセルフホスト + 初回セットアップウィザード(Phase 1)とする~~ **(→ 2026-08-30 改訂 1 で差し替え — 下記。「最初の 5 分」体験要件と正直な切り分けは不変)**

**取り込まないもの(ガードレール)**: `.env` を正にする世界観への寄り戻し(暗号化 `.env` の git 格納・dotenvx 互換を製品の顔にすること・端末ローカル暗号化の `.env.local`)/ リカバリーキットの運営が読める預かり / OS レベルの画面非表示保証・「人間は秘密不可」の既定化 / 「ディスクレス run がある」だけの差別化・機能数でセキュリティを語ること・「絶対最安全」という表現。

**Rationale**: 天井が高いのはゼロ知識チーム基盤(企業が金を払う論点 — 監査・権限・退職時ローテ・セルフホスト・「平文をベンダーに見せない」— に正面から答える)。今いちばん風が吹いているのはエージェント隔離であり、これは ROADMAP Phase 3(MCP・DO リース・credential brokering の土台)として既に方向が合っている。Varlock から盗むのはエージェント隔離の発想だけで、`.env` 世界観を丸飲みすると「Infisical + dotenv 改善」に近づき差別化が死ぬ。原理的に消せない限界(既読値の取り消し・正規端末の完全侵害・可用性・平文の意味的正しさ)は CRYPTO_SPEC §14.3 が既に明示しており、脅威モデル文書(Phase 2)で正直に語り、製品機能(要ローテーション検出等)で補う。

**Consequences**: ROADMAP に反映(Phase 2 のチーム共有へ未登録ユーザー招待 = CRYPTO_SPEC 未決 #9・指紋確認のゼロ知識運用 UX を、ヘッドゴシップへ環境マニフェスト・チェックポイント設計 = 未決 #12 を明記。Phase 3 へ値なしスキーマ・no-reveal 方針化・リーク検知を追加し、credential brokering を `maruhi proxy run` として具体化。将来へ封印バックアップ・四眼承認・上流自動ローテ・ローテ完了窓の機構化 = CRYPTO_SPEC §14.3-5 (ii) を追加)。Phase A(本線を磨く)= 既存 Phase 1〜2、Phase B(エージェント隔離)= 既存 Phase 3、Phase C(真正性残余・企業向け)= 既存 Phase 2 の残余項目 + 将来、に対応し、フェーズの再編は行わない。売り文句は「運営に平文を見せない」→「運営にもエージェントにも平文を渡さない」→「人間が間違えても、秘密がそこにない」へ段階的に進化させる。

## 改訂 1(2026-08-30): 決定 5 の差し替え — ホステッドクラウド版の前倒し(H 系列)

2026-08-30 のオーナー裁定((1) docs サイトは後回し (2) ホステッドクラウド版を最優先し「サービスとして完成」させる (3) 値なしスキーマはフル実施・MCP 配信は後回し)を受けた改訂。裁定の経緯・棄却案は docs/notes/session-47.md(裁定 CY〜DE)、設計・gap 分析・実装分割(H1〜H6)は docs/notes/hosted-design.md を正とする。

1. **ホステッドクラウド版を前倒しし、H 系列として実スケジュールに載せる**。順序は次のとおり(ROADMAP に反映):

   > ドッグフーディング(private preview 込み — 並行・継続)/ S1〜S3(値なしスキーマの署名・受理・検証面)と H1〜H4(サインアップ制御・quota・運用・法務)の並走 → H5 公開儀式(SECURITY.md + 脅威モデル文書 + 公開前チェックリスト)→ **public 化** → 招待制ベータ → オープンベータ → GA(課金・docs サイト)

2. **旧決定 5 の前提への回答**:
   - 「Phase 1 の完了条件(ドッグフーディング)が先」→ **ドッグフーディングを完了条件(先行ゲート)から並行の継続活動へ再定義する**。検証デプロイは 2026-08-10 から実在し(session-19)、Phase 1 の機能面は完了済み — 「数週間待つ」ことに待つだけの価値はなく、H 系列と同時に始めて招待制ベータまで続ける方が学習が速い。「自分の全プロジェクトから .env を消せた」の実証は private preview の第一利用者(所有者自身)が担う
   - 「Phase 2 の公開が先」→ **順序としては維持する(公開 → 外部ベータ)が、根拠を「フェーズの直列」から「ゼロ知識の検証可能性 = 外部テナント受け入れの前提条件」へ置き換える**。E2EE 設計はサーバーを被検証者(不信の対象)として作られており(CRYPTO_SPEC §14)、「運営は読めない」の対外的主張は復号を行うクライアント(CLI / crypto — MIT)のソース検証可能性が支える — 非公開のまま不特定の外部テナントの秘密を預かることは検証不能な約束で秘密を集めることであり、運営の非の最小化(ADR-0018)と逆行する。公開は独立のマイルストーンではなく **H 系列のゲート(H5)** になる。docs サイト(Wave 3 G)は公開の必須物から外す(オーナー裁定 — 公開時は README + SELF_HOSTING で足り、docs サイトは GA までに)
   - 「着工日 = WorkOS 再判断ポイント(ADR-0009)」→ **再判断を実施した(2026-08-30)**: v1 は GitHub OAuth 直実装のまま続行。記録と次の再判断ポイントは ADR-0009 の再判断記録を正とする
3. **「最初の 5 分」体験要件は招待制ベータの開放条件(H6)に具体化する**: サインアップ → 秘密投入 → `maruhi run` までが、Cloudflare アカウント・OAuth App 作成・wrangler なしで完結すること。ゼロ知識の儀式(鍵生成・リカバリーキット保存)は隠さず「初回だけ」と正直に示す(決定 5 の切り分けは不変)
4. **外部テナントを持つ前に署名・ワイヤ面を固める**: 値なしスキーマの S1〜S3(テストベクター・crypto・受理・CLI 検証面)は招待制ベータ開放前に着地する(署名・受理面の変更は外部テナントの存在前が最も安い — session-46 §9 申し送りの解消。S4〜S5 はゲートにしない)。詳細は hosted-design.md §4
5. **ガードレール(取り込まないもの)は不変**。加えてホステッド固有に: 運営が読めるリカバリー預かり・値の運営側エクスポートを提供しない(決定 4 の再確認)、テレメトリゼロと運用観測の線引き・quota の fail-loud(黙って劣化させない)は hosted-design.md §3 / §5 の規範に従う
